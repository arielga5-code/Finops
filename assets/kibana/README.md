# Kibana dashboard

`azure-ai-finops-dashboard.ndjson` — an importable Kibana saved-object bundle for
the Azure AI FinOps dashboard.

Generated by `build_dashboard.py`. Edit the script, not the NDJSON — the NDJSON
is a build output and hand-edits get overwritten.

## Verification status — read this first

**The import has not been tested against a live Kibana.** There was no Elastic
deployment available while building it, so what is verified is:

- every line is valid JSON, and the bundle parses as NDJSON
- the Lens state shape matches the dashboard Elastic ships inside the
  `azure_billing` integration package, used as ground truth rather than written
  from memory
- `columnOrder` matches `columns` on every layer, with bucket columns ordered
  before metric columns
- every panel carries a data view reference, and the dashboard's top-level
  `references` mirror them

What is **not** verified: that Kibana accepts it, that every panel renders, and
that the visualization options are right for your exact version. Saved-object
schemas move between versions. Expect to fix one or two panels on first import;
that is normal for a hand-built bundle, and much faster than building eight
panels from scratch in the UI.

Import into a non-production space first.

## What is in it

Three saved objects:

| Object | ID | Purpose |
|---|---|---|
| Data view | `finops-dv-azure-billing` | `metrics-azure.billing-*` |
| Data view | `finops-dv-azure-openai` | `metrics-azure_openai.metrics-*` |
| Dashboard | `finops-azure-ai-dashboard` | 8 by-value Lens panels |

Panels are **by value** — embedded in the dashboard rather than saved as separate
visualization objects. Fewer objects, fewer references to break on import. The
trade-off is that a panel cannot be reused on another dashboard without copying.

| Panel | Data view | Notes |
|---|---|---|
| Total Azure spend | billing | Sum of `actual_cost`, forecast excluded |
| AI spend | billing | Same, scoped to Cognitive Services / AI Foundry |
| PTU utilization | openai | Avg `provisioned_managed_utilization_v2` |
| Daily AI spend by resource | billing | Buckets on `usage_date`, split by resource |
| AI spend by resource group | billing | Horizontal bar |
| Input vs output tokens | openai | Stacked, hourly |
| Prompt cache match rate | openai | Line, split by deployment |
| AI deployments by cost | billing | Table |

## Import

UI: **Stack Management → Saved Objects → Import**, then pick the file. Choose
"Check for existing objects" so a re-import updates rather than duplicates.

API:

```bash
curl -X POST "$KIBANA_URL/api/saved_objects/_import?overwrite=true" \
  -H "kbn-xsrf: true" \
  -H "Authorization: ApiKey $KIBANA_API_KEY" \
  --form file=@assets/kibana/azure-ai-finops-dashboard.ndjson
```

A successful response reports `"success": true` with `successCount: 3`. If it
returns `success: false`, the `errors` array names the object and the reason —
that is your fix list.

## Two design decisions worth knowing

**Cost panels bucket on `azure.billing.usage_date`, not `@timestamp`.** The
global time picker still filters on `@timestamp`, because that is the data view's
time field and what the picker requires. So the time picker selects *which polls*
to include, and the chart's x-axis shows *when the cost was incurred*. That is
deliberate — see `docs/02-cost-ingestion.md`. It also means a very narrow time
range can look empty: the integration only polls twice a day. Start at 30 days.

**Every cost aggregation carries an `actual_cost: *` filter.** Forecast and actual
documents share the data stream, so an unfiltered sum roughly doubles your
numbers. If a panel shows implausibly high spend, this filter is the first thing
to check.

## Adapting it

The two edits most people want:

**Group by cost center instead of resource group.** Requires the tag-promotion
pipeline from `docs/02-cost-ingestion.md`. Then in `build_dashboard.py` replace
`azure.resource.group` with `finops.cost_center` and regenerate.

**Widen the AI scope.** `AI_SCOPE` at the top of the script decides what counts as
AI spend. It currently matches Cognitive Services, Machine Learning Services, and
any product containing "openai". Add your own resource types there.

Regenerate after any edit:

```bash
python3 assets/kibana/build_dashboard.py
```

## What this dashboard cannot do

Cost per million tokens — the metric that matters most — is **not** on it, and
cannot be. Lens panels query one data view; cost lives in the billing data stream
and tokens live in the Azure OpenAI one. Combining them needs the summary index
described in `docs/04-dashboards.md` and `assets/README.md`. Once that index
exists, the panel is a simple ratio and can be added here.

This is the honest limit of the out-of-the-box path, and it is worth knowing
before you present the dashboard as complete.
