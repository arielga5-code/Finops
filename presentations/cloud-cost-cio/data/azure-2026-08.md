### This contradicts what the deck says about Databricks

Slide 23 and slide 34 state that Databricks bills at $0 because it draws against the
600,000 DBU-hour pre-purchase of 28 April 2026, and that cumulative utilisation was
only **18%** at July. At that rate the balance lasts years, so exhaustion does not
explain August.

Consumption did not jump either: roughly $29.6K/month was being drawn May–July, and
August's billed figure is $30,183 — **the same volume, now costing cash**.

What changed is the meter mix. August's Databricks lines are dominated by serverless
SKUs, several of them new:

| Meter | August |
|---|---:|
| Premium Jobs Compute DBU | $6,554 |
| Premium All-purpose Compute DBU | $4,783 |
| Premium Automated Serverless Compute — Promo DBU | $3,575 |
| Premium Serverless SQL DBU | $3,328 |
| Premium Serverless Realtime Inferencing DBU | $3,104 |
| Premium SQL Compute Pro DBU | $2,804 |
| **Premium Anthropic Serverless Inference DBU** | **$2,098** |
| Premium Interactive Serverless Compute — Promo DBU | $1,874 |
| Premium All-Purpose Photon DBU | $1,473 |

The working hypothesis is that serverless Databricks SKUs draw differently against the
DBCU commitment — or fall outside it — so a workload shift to serverless turned a
drawdown into cash. **This needs confirming with the Microsoft/Databricks account team
before the slide is written**: it is a $30K/month swing, about $362K annualised, and
the deck currently tells the CIO the opposite.

Note also `Premium Anthropic Serverless Inference DBU` — AI inference is now running
inside Databricks as well as in Foundry and Bedrock.

## The tag cuts are not usable from this run

The export returned **100.00% untagged on both Project and CostCenter**, across all
1.1M rows and every dollar.

That is almost certainly a column problem, not a tagging collapse. July was 23.4%
untagged; tagging does not fall from 76.6% coverage to exactly zero in one month, and
a clean 100.00% with a single distinct value is the signature of a column that was
never read. The likely cause is a header this tool did not match — a tag column named
something other than `Tags`.

The aggregator now matches `Tags`, `ResourceTags`, `ResourceTag` and `Tag`, prints
which column it matched for every role, and refuses to present the tag cuts silently:
if no tag column is found it says so and lists the headers it did see.

**Re-run needed** before slides 7 and 8 — the cost-centre and project ownership cuts —
can be built. Everything else in this file stands.
